# インタビューの進め方

実際に起きた選択の経緯から、ジョブ、As-Isの流れ、選択を動かした力を引き出す。
「こういう機能があれば使うか」という未来の質問には好意的な答えが返りやすく、
行動を予測できない。

## 対象

- 最近（記憶が具体的に残っている期間）に使い始めた人、乗り換えた人、やめた人を選ぶ。
  検討して以前のやり方へ戻った人、何もしないことを選んだ人も対象にする。
- 人数は固定しない。判断に関わる新しい状況や理由が出なくなった時点で止め、件数と
  対象の偏りを報告する。言葉の近さではなく、選ぶ前の状況・迷い・行動の流れが
  共通しているかで束ねる。

## 時系列で聞く

「なぜですか」と一気に理由を求めず、「最初に困ったのはいつか」「その直前は何をしていたか」
「ほかに何を試したか」と出来事の順に聞く。

| 段階 | 聞くこと | 見えるもの |
|---|---|---|
| いつもの状態 | 普段はどうしていたか | 現在の解決策、慣れ |
| 最初の違和感 | いつ、何が起きて、今のままでは困ると思ったか | 状況、現状からの押し出し |
| 探し始め | その後どうしたか、誰に相談したか | 関係者、知識の依存 |
| 比べた候補 | 何を比べ、何を試し、何を選ばなかったか。それぞれの理由 | 引力、比較の基準 |
| 決め手 | 決める直前に心配だったこと、決め手になった出来事 | 不安、判断した人 |
| 選んだ後 | 最初に「これで良い」と思えた時点、やめかけた時点、今も残る以前の手順 | 成功の基準、つまずく箇所 |

各段階でかかった時間、待ち、やり直しも聞く。As-Isの流れと最大の制約の材料になる。
流れを助けたことも聞き、To-Beで壊さないものとして残す。

## 避けること

- 機能名や自社の言葉で誘導する。利用者の言葉で状況を話してもらう。
- 満足度の点数だけを聞く。点数の背後にある出来事を聞く。
- 一般論（「普段は」「みんなは」）で終える。直近の一回に絞る。
- 四つの力や感情・周囲との関係を、聞き手の想像で埋める。

## 記録と分析

- 「事実」「推測」「まだ分からないこと」を別の欄に書く。引用は本人の言葉のまま残す。
- 個人情報は分析に必要な範囲だけ残し、録音・記録の保存は同意を得た範囲に限る。
  生成AIへ渡すときは個人を特定できない表現に直し、出力は推測として扱う。
- インタビューができないときは、問い合わせ、レビュー、ログを使う。ログは行動の観測だが
  動機は分からないため、動機の記述は仮説として扱う。
