# Turn an Idea into a Decision

Read the project and settled decisions. Identify the intended user outcome,
constraints, and the uncertainty that could change the implementation.
Investigate factual questions; ask the user about priorities only when needed.

Recommend an approach with the tradeoffs that matter and observable acceptance
criteria. Use alternatives when they expose a real choice.
For uncertain feasibility, use an authorized bounded experiment with a question
and stopping condition. Label prototype limitations.

Break work into independently verifiable slices when useful, preserving the
whole requested scope. Continue into implementation if it was requested and
the important choices are resolved. A design-only request ends with the design;
save a document only when requested or required by the repository.

For a requested decision interview, follow dependencies and ask one material
question at a time. For authorized independent review, use
[review criteria](spec-document-reviewer-prompt.md).
Use the [visual companion](visual-companion.md) only for an accepted visual workflow.
