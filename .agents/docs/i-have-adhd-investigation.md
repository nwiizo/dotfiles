# i-have-adhd の取り込み判断

確認日: 2026-09-19。対象は [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) の `main`（確認時の先頭コミット: `b15d0be58f55b33972ba3e39709e0e5208ef30cb`）。

## 何を提供するか

上流の中心は、読者が回答を理解するだけで止まらず、次の操作へ移れるように応答の形を固定する手動スキルである。主な規則は次のとおり。

- 次の操作を先頭に置き、複数手順を番号付けする
- 継続中の状態を毎回言い直し、完了したことを見えるようにする
- 脇道を抑え、エラーを事実ベースで書く
- 曖昧な時間表現を避け、一覧を小さく保つ
- 明示的な形式、詳細説明、安全確認、曖昧さには例外を認める

[上流の公開評価](https://github.com/ayghri/i-have-adhd/blob/b15d0be58f55b33972ba3e39709e0e5208ef30cb/evals/RESULTS.md)は、Claude Opus 4.8、14ケース、各3回の比較で、候補の重み付きスコアが 4.045 から 4.473 に上がったと報告している。改善は特に進捗報告（actionability）と簡潔さに集中した。一方、agent-owned edit のケースはツールなしの評価条件では判定不能で、partial-success では根拠以上に原因を断定する退行が報告され、リリース基準自体は未達だった。したがって、これは採用候補の根拠であって、全タスクへの効果保証ではない。

## nwiizo-style への反映

以下を既存のClaude/Codex共通の応答方針と `nwiizo-coding-style` に統合した。

- 結果または次の操作を先頭に置く
- 継続中の状態、完了した確認、残る失敗を同じ更新で分けて示す
- 手順を区切り、脇道・重複・感情的な前置きを減らす
- 見積りや原因を、根拠のある具体的な表現に限定する
- 一覧は分類・優先順位付けし、重要な指摘を落とさない

## そのまま採用しなかったもの

- 常時フック、フラグファイル、プラグインマニフェスト: 既存のスキル読み込みと会話内方針で足り、セッション状態を増やす必要がない
- スキル名や診断を前面に出すこと: nwiizo-style の応答方針として扱い、読者へ属性を当てはめない
- 「常に」時間見積り・次の操作・最大5項目を要求すること: 単純な回答、完了済みの報告、明示形式ではノイズになるため条件付きにした
- 上流の全文コピー: 既存の実装・検証・安全・言語方針と重複し、適用範囲が広がりすぎるため採用しない

この文書は外部の実装を追随するためではなく、採用した判断と境界を再確認するためのメモである。上流を更新するときは、評価条件と退行報告を読み直してから方針を変更する。
