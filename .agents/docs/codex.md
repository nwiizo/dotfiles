# Codex Notes

Use this file as routing guidance for the dotfiles-managed Codex assets.

## Placement

| Need | Put it in |
|---|---|
| Durable repo instructions | `AGENTS.md` |
| Repo skills | `.agents/skills/<name>/SKILL.md` |
| User skills | `.agents/skills/` linked to `~/.agents/skills` |
| Project custom agents | `.agents/codex/agents/*.toml` exposed as `.codex/agents/` |
| User custom agents | `.agents/codex/agents/*.toml` linked to `~/.codex/agents/` |
| Command approval rules | Untracked `~/.codex/rules/*.rules` |
| Hooks or MCP config | `.codex/` only when project-trusted and intentionally shared |

## Rules

- Keep `AGENTS.md` small and repo-specific. Use nested `AGENTS.md` files for
  narrower ownership boundaries.
- Use skills for repeatable workflows with clear descriptions. Keep each skill
  focused on one job and prefer instructions over scripts unless deterministic
  tooling is needed.
- Use custom agents for specialized, noisy, or parallel work. Reviewer agents
  should stay read-only and report findings only.
- Do not track local approval rules generated by Codex, because they often
  contain machine-specific commands and project paths.
- Use `.agents/codex/agents` as the source for reusable Codex agent definitions;
  `.codex/agents` is only the project entrypoint symlink.
