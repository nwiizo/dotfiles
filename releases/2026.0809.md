# 2026.0809 — Git-only workflows and explicit agent contracts

This release removes the remaining Jujutsu workflow surface, makes agent
implementation contracts discoverable across Claude Code and Codex, and
improves concurrent Neovim and AI-agent editing.

## Highlights

### Git-only version control

- Removed `jj` from `Brewfile` and retired its Fish helpers, Warp workflow,
  reviewer pair, and shared workflow skills.
- Replaced the `Alt+J` repository picker with `git_fzf_ghq`, which validates the
  selected ghq directory as a Git worktree before changing directory.
- Standardized repository and agent guidance on `git status`, `git diff`, Git
  branches, and Git-only commits and pushes.
- Extended the agent audit to reject active `jj` or Jujutsu references. Removing
  a formula from `Brewfile` stops managing it but does not uninstall an existing
  local binary.

### Agent rules, skills, and planning

- Added global Codex guidance through `.agents/codex/AGENTS.md` and linked the
  shared RTK guide into both Claude Code and Codex homes.
- Adapted Ponytail's solution ladder into local rules and
  `home-karpathy-guidelines` without installing the upstream plugin, hooks,
  modes, or runtime state.
- Added `home-data-shape-contract`: schema, persisted config, payload, and JSON
  shape changes require concrete before/after examples, compatibility impact,
  and user agreement before migration, serializer, or DDL implementation.
- Added `home-test-driven-development`: non-trivial behavior changes use an
  honest focused RED, the smallest GREEN change, and refactoring only while the
  focused and neighboring tests remain green. Prose, generated output,
  config-only edits, and trivial pass-through code are explicit exceptions.
- Strengthened the planner pair to produce an executable file map, cross-cutting
  constraints, interface handoffs, exact verification commands, and no
  unresolved placeholders.
- Changed `home-self-review` to run the opposite AI CLI as a read-only,
  ephemeral reviewer, with a recursion guard, explicit failure handling,
  `commit <SHA>` support, and `second` / `all` reviewer modes.
- Expanded agent-config validation to cover global Claude links, the shared
  Codex RTK link, portable skills, and removed-tool references.

### Neovim and agent collaboration

- External AI-agent edits now auto-reload clean buffers and 3-way merge disk
  changes with unsaved Neovim changes using the buffer-open snapshot as the
  common base.
- Non-conflicting edits preserve both sides. Conflicts remain in the unsaved
  buffer with diff3 markers; deletions, non-UTF-8/binary buffers, missing Git,
  and unavailable merge bases fall back to an explicit prompt.
- Added lazy command triggers for Signalbox update-all and resume operations and
  refreshed pinned Neovim plugin revisions.

### Intentional unrestricted AI aliases

- `c` expands to `claude --dangerously-skip-permissions`; `cc` keeps normal
  Claude Code permissions.
- `cx` expands to `codex --dangerously-bypass-approvals-and-sandbox`; use `cxs`
  for workspace-write with approval prompts or `cxro` for read-only operation.
- These unrestricted short aliases are an explicit local policy, not an
  implicit safety default.

## Apply

```bash
brew bundle --file Brewfile
./scripts/link.sh
fish scripts/install-fish-plugins.fish
exec fish
```

Restart Neovim and start new Claude Code or Codex sessions after applying agent
and editor changes.

## Verification

Run the repository agent audit, Fish and Neovim syntax checks, and a headless
Neovim startup check. Exercise the external-edit merge against a scratch file
with non-conflicting and conflicting local/disk edits before relying on it for
unsaved work.
