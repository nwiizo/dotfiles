# GitHub Comment Writing

GitHub の Issue / PR で、確認・判断を依頼するコメントを書くときの規則。

- 承認だけを求めず、相手が判断に参加できる理解を作る。必要な背景と、利用者から見える動作を先に短く説明する
- 現在確認できている事実、推奨案、相手に回答してほしい質問を分ける。実装者側で決められる事項は質問にせず、方針として示す
- 1つの質問には1つの判断を置き、回答によって何が決まるか分かる形にする。独立した論点を一度に詰め込まない
- Issue の受け入れ条件と最新コメントを読み、既に決まったことを聞き直さない。別 Issue の論点は適切な場所へ移す
- 似た概念、件数、状態遷移が誤解されやすい場合だけ、短い具体例を添える。図は理解を明確に改善するときだけ使う
- 日本語として自然な語を使い、英語の直訳や説明のない専門語を避ける。ソフトウェアの方針や振る舞いには「方針」「取り決め」「動作」など内容を直接表す語を使い、観測できる動作を書く
- 返信が付く前に文章を整理する場合は、補足コメントを重ねず既存コメントを編集して情報を一箇所に保つ
